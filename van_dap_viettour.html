1. Module Danh Sách Yêu Thích (Wishlist)

Lưu giữ tour yêu thích, chống trùng lặp dữ liệu và giao diện phản hồi tức thì (Optimistic UI)

Module 01
Kịch bản trình bày 30 giây trước thầy cô:
"Dạ thưa thầy/cô, chức năng Yêu thích tour cho phép khách hàng lưu lại các tour ưng ý vào danh sách cá nhân. Về mặt kỹ thuật, hệ thống dùng cơ chế Optimistic UI: khi bấm tim, giao diện đổi màu đỏ ngay lập tức và gửi API ngầm, nếu có lỗi mới hoàn tác lại. Dưới Database, bảng wishlist được đặt khóa duy nhất UNIQUE(user_id, tour_id) để đảm bảo 1 user không bao giờ bị lưu trùng 1 tour nhiều lần."

3. Module Cài Đặt Người Dùng (Profile & Security)

Cập nhật thông tin cá nhân và quy trình đổi mật khẩu mã hóa Bcrypt an toàn

Module 03
Kịch bản trình bày 30 giây trước thầy cô:
"Dạ thưa thầy/cô, Module Cài đặt người dùng quản lý thông tin định danh và bảo mật tài khoản. Mật khẩu khách hàng được bảo vệ bằng giải thuật Bcrypt với 10 vòng salt, tuyệt đối không lưu plain text. Khi đổi mật khẩu, backend bắt buộc kiểm tra mật khẩu hiện tại bằng bcrypt.compare(), nếu đúng mới tiến hành mã hóa mật khẩu mới và ghi đè vào DB."

5. Module Quản Lý Booking Phía Quản Trị (Admin Bookings)

Kiểm soát danh sách đơn, sắp xếp realtime, duyệt hoàn tiền và nhả ghế trong Database Transaction

Module 05
Kịch bản trình bày 30 giây trước thầy cô:
"Dạ thưa thầy/cô, Module Quản lý Booking của Admin là hạt nhân vận hành của công ty. Tóm Tắt 5 Bảng Dữ Liệu Tương Ứng 5 Module

Cấu trúc schema cơ bản bạn cần nhớ trong database db_viet_travel

Schema
Module Tên Bảng Khóa Chính / Khóa Ngoại Ràng Buộc Kỹ Thuật Đáng Chú Ý
1. Yêu thích wishlist PK id, FK user_id, tour_id UNIQUE(user_id, tour_id) (Chống lưu trùng)
2. Đánh giá reviews PK id, FK user_id, tour_id UNIQUE(booking_id) (1 vé đi tour chỉ đánh giá 1 lần)
3. Cài đặt users PK id password băm Bcrypt 10 rounds, email UNIQUE
4. Lịch sử bookings PK id, FK user_id, departure_id Lưu status và payment_status độc lập
5. Quản lý Booking tour_departures PK id, FK tour_id seats_available được hoàn/trừ tự động trong Transaction

Top Tips

1. Trả Lời Trọng Tâm Vào Kiến Trúc

Khi được hỏi bất kỳ tính năng nào, hãy trả lời theo đúng luồng: UI → API → Controller → Service → Repository → Database. Nhấn mạnh rằng Controller không query DB mà nhường toàn bộ cho Service và Knex Repository.

2. Nhấn Mạnh Tính Toàn Vẹn Dữ Liệu (ACID)

Thầy cô rất thích hỏi về việc "Ghế có bị mất không? Tiền hoàn có bị lệch không?". Hãy luôn khẳng định nhóm dùng Database Transaction để bảo toàn số lượng ghế và dùng parseDepartureDate() tách chuỗi YYYY-MM-DD để tránh lỗi múi giờ.
